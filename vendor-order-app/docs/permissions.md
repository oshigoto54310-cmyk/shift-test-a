# 権限一覧

## 権限の種類

| コード | 名称 | データ参照範囲 |
|---|---|---|
| `ADMIN` | 管理者 | 全店舗・全ベンダー |
| `HQ` | 本部担当者 | 全店舗・全ベンダー |
| `STORE` | 店舗担当者 | **自店舗のみ** |
| `VENDOR` | ベンダー担当者 | **自ベンダーのみ** |

## データ分離の実装

### 1. サーバー側でのスコープ強制

すべての検索は `app/deps.py` の `build_scope()` を通ります。

```python
if role == RoleCode.VENDOR:
    if requested_vendor_id is not None and requested_vendor_id != user.vendor_id:
        raise forbidden("他ベンダーのデータにはアクセスできません")
    return AccessScope(vendor_id=user.vendor_id, ...)   # 自ベンダーに固定
```

クライアントが `?vendor_id=2` を送っても、自分のスコープ外なら **403** を返します。
黙って自分のスコープに読み替える実装にしていないのは、
「データが無いのか権限が無いのか」を区別できず実装ミスに気づけなくなるためです。

### 2. 個別リソースへのアクセス制御

発注1件を開くときは `get_order_for_user()` が店舗軸とベンダー軸の両方で判定します。
URL の ID を書き換えても、権限外の発注は 403 になります。

### 3. 出力への適用

出力APIも同じスコープを使うため、Excel・CSV・PDF のいずれでも他社データは含まれません。

これらは [`backend/tests/test_permissions.py`](../backend/tests/test_permissions.py) と
[`backend/tests/test_exports.py`](../backend/tests/test_exports.py) で自動検証しています。

## HTTPステータスコードの使い分け

| コード | 意味 | 例 |
|---|---|---|
| 401 | 未認証 | 未ログイン、セッション期限切れ |
| 403 | 権限不足 | 他店舗・他ベンダーへのアクセス、CSRFトークン不一致、アカウント停止 |
| 404 | 対象が存在しない | 存在しないID |
| 409 | 業務ルール上の競合 | 締め後の直接変更、二重送信、二重確定、処理済みの申請 |
| 422 | 入力形式エラー | 必須項目不足、同一商品の重複行 |
| 423 | ロック中 | ログイン失敗によるアカウント一時ロック |
